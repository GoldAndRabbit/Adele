# 歌曲与演唱会工作流

唯一总入口为 `.venv/bin/python -m workflow.live`。按 [标准工作流](../../docs/workflow.md) 运行七个模块；文案与封面填字按 [模板规范](../../docs/design/publication_templates.md)。

- 单曲登记 `new NAME --kind single --url LINK --song-title TITLE`，演唱会登记 `new NAME --source PATH`，补充真实艺人和演出资料。两者进入相同逐首流程。
- 默认 `run NAME` 准备到封面，不自动制作或投稿；用户已确认预览后使用 `--from delivery --to delivery --confirmed`。已有授权持续有效，无需重复询问。
- 默认双Mac，每台一首，调度在 `live.pipeline`，机器槽位在 `runtime.HostPool`。不创建日期目录中的Python编排脚本。
- 暂停停止派工、当前歌收尾；恢复加 `--resume`。故障按首隔离，保留实际日志，不重复启动。
- 已确认队列直接复用字幕、封面、投稿资料，只制作缺少的所选渠道成品；不隐式触发ASR、重翻译或额外内容听审。
- 字幕按现场实际演唱匹配参考，串烧和现场改词遵循ASR；讲话、歌词和语气词按正式字幕模块处理，人工修改进入正式定稿表。
- 投稿标题字段、80字符预算、1800–2000字符三部分简介、标签限制及人工覆盖规则由正式模板与生成器决定。页面、完整JSON、复制与导出共用 `submission_records`。
- AI封面走FIBO原帧、母图、排版、精确版本复核发布；新封面与新成品都通过 `write_bundle` 同步路径、机器和用时，不手写另一份投稿信息。
- 插帧与工作缓存在内置盘，原片和最终产物在外盘。B站单渠道默认苹果流式编码，不生成中间视频／帧图片；编码预设统一在 `encoding.py`。
- 制作不等于发布。投稿仅按明确授权执行，凭真实回执判断成功；待提交但无回执时先查重。
- 不读取或展示凭证。媒体、人工定稿、回执和历史数据不得随代码清理删除。
