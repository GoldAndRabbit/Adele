# v4：v3 + 观众合唱检测

v4 单独一个目录 `workflow_v4/`，从 `workflow_v3/` 复制出来后单独维护，两边不共用代码：改 v4 不影响 v3，v3 也不再有观众合唱检测。

| | v3 | v4 |
|---|---|---|
| 代码 | `workflow_v3/` | `workflow_v4/` |
| 结果 | 每首歌的 `exp_v3/` | 每首歌的 `exp_v4/` |
| 观众合唱检测 | 没有 | 有（`song_crowd_workflow.py`） |
| 其余步骤（识别、对齐、翻译、注释、水印） | 原样 | 复制时和 v3 一样，之后各改各的 |

## 流程

```
听（多遍识别）→ 整首顺序对齐 → 锚点 → 锚点之间重新识别、再对齐
  → 观众合唱检测（v4 才有）
  → 歌词外段落 → 时间 → 显示 → 翻译（song_translation_workflow）→ 注释（song_note_workflow）
```

观众合唱检测在两个可靠锚点之间找「有人声、识别很碎、按歌词顺序该唱 ≥ 1 句」的区间，各项证据独立打分：
识别碎片、立体声、主唱音高稳定度、画面（Qwen-VL 看 3 帧）、提示语（canten / sing / everybody …）、歌词顺序。
判成观众合唱的段，该唱的句子按 Genius 顺序排进去，时间按录音室版 LRC（lrclib.net）的时长比例分。
检测结果写到 `exp_v4/crowd.json`，审核页表格里「唱法」列标出来。

### 唱速自检（2026-10-20 加）

判成合唱后，算「这段该唱的句子按录音室唱速要唱多久 / 这段实际多长」；超过 `PACE_MAX = 1.5`（按 1.5 倍速也唱不完）
就说明现场在这里跳过了歌词、不是观众按原词合唱，改判「不是」，这段保持 v3 原样。没有录音室时间轴的句子，
按这首歌已对上句子的中位时长估。

| 段 | 该唱 | 录音室要多久 / 段长 | 结果 |
|---|---|---|---|
| BZRP 3:08、3:32 | 1 句 | 0.6、0.3 | 对 |
| Antología 2:07 | 4 句 | 0.7 | 对 |
| Dai Dai 2:01 | 2 句 | 0.6 | 对 |
| Sarà perché（2023）2:15 | 16 句 | 4.0 | 错（现场即兴，被塞进整段副歌）→ 自检拦下 |

（时间是歌曲内时间；审核页预览多留了 10 s 的歌，表格时间 = 歌曲内时间 + 10 s。）

### 已知局限：分不清「观众在唱」和「歌手在喊 / 改词 / 全场欢呼」

识别碎片、主唱音高、立体声这三项，在歌手喊话、现场改词、全场欢呼时也会成立，所以会误判。
2026-10-20 全部 29 首里一共判出约 20 段合唱，其中判对的（v4 明显更好）：Antología 2:07、Pies descalzos 0:56、
Suerte 2:10、Loca 0:22、BZRP 3:32；判错的：Hips Don't Lie 2:31（歌手喊「Yeah, oh, yeah」）、Las de la intuición 0:31
（丢了两句真唱的歌词）、Empire 4:01 / 4:15、Loca 1:38（把上一句重复了 10 秒）。

试过用画面否决（看图模型说歌手在对着话筒唱就不算合唱）：能去掉上面判错的，但也会去掉 Antología、Pies descalzos、
Loca 开头、Suerte 这些判对的——每段只看 3 帧，镜头在歌手和观众之间切，不可靠。所以**没有加**。

**结论：判出合唱段的歌，由人听一下那几段再定**（每首 0～3 段）。审核页「合唱检测」行列出这段排进去的合唱字幕和
v3 同一段原来的字幕，方便对比；要去掉哪段，只把那一段换回 v3（不用重跑）。

### 撤掉的规则：识别结巴

为 Emptiness Machine 2:31 的重复加过「一遍识别里同一个词 2 s 内又出现、另外两遍只听到一次 → 不和歌词对上」，
在 Waka Waka 的口号段误伤（2:35～2:44 丢了 4 句），已撤掉。v4 的对齐代码和 v3 完全一样。
Emptiness Machine 的 v4 结果是带这条规则时跑的（2:31 已合并成一句），没有重跑。
