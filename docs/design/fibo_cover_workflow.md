# FIBO 演唱会封面母图流程

## 双 Mac 连续队列

入口为 `workflow.fibo_dual_queue`。两台机器从同一个歌曲清单领任务，
每台一次处理一首，不按整场等待。队列锁防止重复启动，逐曲锁防止重复领歌，
两台各自的 GPU 锁也与人声分离共用。旧进程应先完成当前歌曲再交接；
不能只终止父进程而留下正在推理的子进程。

```sh
.venv/bin/python -m workflow.fibo_dual_queue \
  work/three-concert-subtitles-20261114/dual-cover-queue.json \
  --model /Users/gold/Library/Caches/adele/fibo2-edit-turbo-q4 \
  --remote-config work/three-concert-subtitles-20261114/remote-fibo.json \
  --remote-ready work/three-concert-subtitles-20261114/remote-fibo-ready.json \
  --auto-review
```

副机配置包含 `host`、SSH `identity` 和远端 `directory`。只传本曲清理后的
参考帧、公开提示词及推理参数，不同步密钥或整个项目。模型预备完成且逐文件
SHA256 比对通过后才写 `remote-fibo-ready.json`；这个标记不代表已经生图。
16 GiB 副机使用同一 FIBO 2 Edit Turbo 的 MFLUX Q4 权重，在 CPU 逐参数载入后
转 Metal 推理，母图为 768×432，Metal 内存预算 12 GiB。主机默认母图为
1024×576。两边均由标准排版生成相同规格的四张平台封面。
远端工作目录为 `~/Library/Caches/adele/fibo-worker/jobs/<任务ID>`，
实际生成日志、耗时及峰值内存回传本曲运行目录，并核对成图 SHA256。
中断重连复用同一远端任务及成功回执，不重复推理。

启用 `--auto-review` 后，每首完成即调用现有 `vision_json`，把原帧、母图和
四版成品一起核对。所有明确检查项通过且问题列表为空才调用标准
`reviewed_cover.publish`，随即更新 B站、抖音投稿资料及四个规范文件路径，
再从页面接口取图核对摘要、尺寸和专辑缩略图。页面缓存延迟只重试验证，
不重做母图。检查记录标明机器视觉复核，不冒充人工审核。
拒绝结果单独记录原因，原版本不发布；已有通过复核的封面直接复用。
`PAUSED` 位于队列 JSON 同目录，暂停后不再领取下一首。

用户明确要求重选已有封面时，为指定歌曲建立独立队列并加
`--replace-existing --auto-review`。此模式重新选择原片镜头并生成新版本，
旧版封面在新版本通过视觉复核前保持可用，不清空原母图或投稿附件。
重跑同一队列会复用本次已通过的新版本，不把历史旧封面当作重做完成。

退回后使用 `--reselect-rejected` 接续同一队列。`workflow.fibo_dense_samples`
每两秒扫描本曲实际预览片段，保存 `showinfo` 的真实帧时间，按睁眼、脸部清晰度
和镜头间隔筛出候选，再由标准视觉入口确认主艺人。新的候选会排除已退回帧，
不能把镜头中的伴舞当主唱。竖版可裁去边缘伴舞或观众，仍须完整保留主唱；
署名合作歌手按合作曲规则处理。原帧暗部不得被画成新增清晰人脸或乐器。

人脸难例可从同一时间码的原生分辨率原帧提取身份细节，走
`workflow.fibo_identity`。第二张参考仅用于同一人的五官，主参考仍决定整幅构图。
`composition-detail-v1` 保留主参考的输出画幅，身份参考单独采用较小像素预算，
避免两张参考等大时把全景误改成面部特写。身份裁切及原帧摘要、实际预算、
执行机器均写入生成记录，并参与缓存或复核摘要。

持续重绘仍改变实际动作时，使用已有 `reviewed_cover.stage` 的
`palette` + `preserve_stage` 分支。它只迁移 FIBO 色调及有限笔触，保留原片
人物、动作和舞台几何，标为“FIBO 笔触 · 原帧保真”、`source_with_ai`。
该分支不计作完整 AI 重绘，四版仍须逐一复核及同步。2026-11-15 三场批次的
《Bloody Mary》采用此分支，其他45首为完整 AI 母图。

## 选帧

选帧时同时检查主唱、合作歌手和近处伴舞。放大核对眼睛：双眼视线一致，只选睁眼的可见人物，避开背影、极端仰拍、张口紧绷或眼神变形；优先自然平视、对视或微笑的瞬间。原帧与母图并排逐人核对，新增的背景人脸、巨幅投影或抢镜人物均需返工。避开半睁、翻白眼或两眼方向不一致；自然侧脸按原片保留单眼。缩到列表尺寸后再确认主角一眼可辨。优先选话筒在唇边或放低、双眼及鼻部清晰的瞬间；话筒挡住五官时回本曲重选。独唱和有明确主艺人的嘉宾合唱，先按本场署名辨认主唱，再比较脸部大小、明暗和前后位置。主唱应一眼可辨；嘉宾、乐手或伴舞抢占前景时，回本曲换镜头。为新参考帧记录主唱脸中心的归一化横坐标 lead_face_x；原帧及母图以此复核主唱，其他脸同大或更大时退回选帧。合唱同时比较同框和主唱正面单人候选，优先五官清楚、神情自然、构图好的画面。选择同框时在 3:4 中核对双方，选择单人时核对主唱身份和正脸，保留完整演出署名。导出前检查每个比例的完整品牌角标，朝阳Adele 与 4K 60 FPS 固定左上角上下排列。遇到人脸重叠时先调整画面取景，仍冲突就换帧。


批处理会在推理前检查参考帧，并在发布前检查母图。Apple Vision 检出的疑似闭眼帧进入人工复核，队列继续处理后面的歌曲。确认属于墨镜、遮挡或关键点误判时，可在本曲计划的 `eye_review.reference` 或 `eye_review.master` 保存该图的 `sha256` 和复核原因 `reason`。更换图片后需重新核对。

从同一镜头前后约一秒的原片里比较表情、握姿、麦克风位置和清晰度。优先保留动作和表情合适的清晰单帧。手部轻微运动模糊可以随油画绘制处理，生成后要与原片核对。邻帧中动作不同的手会改变生成结果的姿势。

## 清理原帧

入口为 `workflow/fibo_cover.py`。OpenCV 将画面归一到 768 像素宽，在右上角匹配 LIVE 7 HD 台标。整块匹配分数达到 0.80，或整块达到 0.55 且 LIVE、7、HD 三部分分别达到 0.75 时，按台标笔画在原分辨率修补，再次检测清理后的参考帧。复检分数达到 0.55 即暂停生图。

2014 格莱美的 TS 来源默认要求识别该台标。其他来源可在单曲计划里设置 `expect_live7`，单张试跑加 `--expect-live7`。预期台标未识别，或遇到疑似台标时，先核对原帧再继续。原帧留作对照，预处理版本参与母图缓存键。新增转播源须核实其台标图案、位置及尺度。

在仓库根目录运行。每次提供一个新的输出目录，省略权重参数即可只检查预处理。

```sh
.venv/bin/python workflow/fibo_cover.py \
  work/local-flux3/bf16-close/d1169-05.jpg work/royals-check
```

查看 `reference.png` 和 `preprocess.json`。记录中有原帧路径、模板、匹配分数、命中区域及耗时。台标与人脸、乐器细节重叠时应检查修补结果，必要时换帧。

## 生成与验收

```sh
.venv/bin/python workflow/fibo_cover.py \
  work/local-flux3/bf16-close/d1169-05.jpg work/royals-paint \
  --model /Volumes/harddisk_5T/adele-workflow/work/flux3/models/fibo2-edit-turbo-bf16
```

默认使用本地 MFLUX 环境、单张清理后的参考帧、1024×576、4 步、guidance 1、种子 42。可用 `--prompt` 指定演出风格和需要保留的动作。模型生成一张无字母图。运行目录包含母图、MFLUX 元数据、原片对比、日志、生成耗时和进程峰值内存。

选帧时放大检查主唱和清晰可辨的背景人脸。遇到眨眼瞬间，优先从本曲相邻镜头换帧；合唱仍需保留主要演唱者同框。母图生成后，再核对眼神、握姿、麦克风位置和台标区域。通过后将同一张母图交给封面排版环节制作各比例，在排版环节加入歌名、艺人和演出信息。这个入口供单张试跑使用。

## 单张母图制作带账号标识的横版封面

用歌曲资料填入主标题和第二行（歌手中文名、英文名、演出简称、字幕语言）。在母图上居中排两行字，左上放项目的「朝阳Adele」透明标识，正下方放「4K 60 FPS」徽章。文字和标识在本地合成，改字或改稿可直接复用母图。

```sh
.venv/bin/python -m workflow.ai_cover grammys_2014 02_royals \
  work/local-flux3/royals-logo/trial/master.png \
  --branded-output work/local-flux3/royals-logo/trial/royals-cover-16x9.jpg
```

此命令只写一张 1920×1080 JPEG 供审稿。检查缩略图上的第二行可读性、主标题与眼口的位置、左上两枚标识的间距，再决定是否采用。

## 生成后更新审核 UI

在生成命令中追加 `--preview-song grammys_2014 02_royals --source-time 1170`（时间为参考帧在对应原片中的秒数）。成功后登记实际输入的清理帧、无字母图、完整提示词、模型标识及推理框架版本、生成耗时、任务起止时间和峰值内存，并用紧凑双行标题排出 B 站 16:9 / 4:3、抖音 3:4 / 4:3。

横版与竖版统一在左上角叠加朝阳Adele 和 4K 60 FPS。横版前者宽度为画布宽度的 17%，后者约为 13.8%。竖版分别为 18% 与约 14.6%，两者水平中心对齐。位置固定为距左 60 px、距顶 34 px，徽章与 Logo 间距 10 px。生成与发布校验共用 `workflow/cover_brand.py` 中的配置，逐曲的历史 `brand_scale` 参数不参与尺寸计算。

| 版本 | 画布 | Logo 宽度 | 4K 徽章宽度 |
| --- | --- | --- | --- |
| B站 16:9 | 1920 × 1080 | 326 px | 265 px |
| B站 4:3 | 1440 × 1080 | 245 px | 199 px |
| 抖音 3:4 | 1080 × 1440 | 194 px | 158 px |
| 抖音 4:3 | 1440 × 1080 | 245 px | 199 px |


四张成品分别按画布宽度实测标题字形，目标宽度为画布的 89%，字号上限为短边的 22%。一至三个词的英文标题保留单行，斜杠不计作词。其他标题在单行字号低于画布短边的 7% 时才比较双行排版，优先在串烧的曲名分隔处断行。两行歌名共用同一字号。三首及以上的串烧在封面与卡片显示“首曲名等串烧”，完整曲单保存在歌曲详情。两首联唱保留双曲名，署名行只写艺人与演出。署名行使用自然字距，独立居中，字号以画布短边的 6.2% 为上限，长署名按画布 89% 的安全宽度缩小。字高上限为主标题实际字高的 64%。抖音 3:4 将整组文字的字形底边设在画面高度的 83% 处，底部 17% 留给播放量标记。横版的歌名与署名整体对齐到 80% 高度的底线，底部 20% 留给播放量、弹幕数和时长。调整文字位置时，从已登记的母图沿用原裁切，只重排受影响的比例。

已有母图可单独补预览，或修改排版后重新运行以下命令。历史运行通过日志修改时间和实测总耗时估算起止时间，UI 会标注；新任务直接记录带时区的时间。

```sh
.venv/bin/python -m workflow.fibo_previews grammys_2014 02_royals \
  work/local-flux3/royals-logo/trial --source-time 1170
```

## 整场复用提示词

默认模板 `concert-oil-v1` 用本地代码将三部分顺序拼接：统一油画处理与构图约束、所选帧的可见细节、人物保真与无字画面要求。每帧用一两句英文记录实际可见的姿态、乐器、视线或灯光。没有观察依据的细节留空。歌曲标题和署名由后续排版加入。单张命令用 `--scene-note` 提供观察；`--prompt` 可完整覆盖模板。

整场参考计划位于 `concerts/<场次>/fibo-cover-plan.json`。每首记录参考图、原片秒数、观察句，可按需指定竖裁位置。例：

```sh
.venv/bin/python -m workflow.fibo_concert grammys_2014 \
  --model /Volumes/harddisk_5T/adele-workflow/work/flux3/models/fibo2-edit-turbo-bf16
```

批次逐曲生成并登记页面，一首一张无字母图、四个本地排版版本。运行记录、原片对比、逐曲资源统计在 `work/fibo-batch/<场次>/`。同一参考帧、提示词、模板版本和权重目录名可复用已完成的运行。

## 左侧清单批量生成

`workflow.fibo_library` 从审核 UI 的 `/api/concerts` 读取实际可见的场次和曲目，并将艺人分组映射回 singles 歌目。运行 `.venv/bin/python -m workflow.fibo_library sample`，从每首歌已确认的原片区间生成带编号的选帧表。原片路径、修改时间和片段起止一致时，可直接读取该曲的干净切片。选定参考帧后保存到本曲的 `covers/ai/references`，并在场次计划记录原片绝对时间、画面观察和竖裁位置。需要去除底部转播条时，核对实际画面后填写 `trim_lower_band`。

运行 `.venv/bin/python -m workflow.fibo_library render --model /本机/FIBO权重目录`。可通过 `--group` 单独处理某个左侧分组。已登记的本地母图直接排四版，待选帧曲目单独记录。程序从页面接口读取四张图并校验实际尺寸后，才把曲目标为 verified。进度保存在各场次的 `sidebar-render.json` 中。需要暂停时在 `work/fibo-batch` 中建立 `PAUSED`，移除后重跑同一命令可续接。
