# 歌曲字幕翻译 workflow（song_translation_workflow）

> 2026-10-19，待确认。确认前不改代码。
>
> **背景**：现在有两套翻译，都是这几天陆续加出来的。
> - v1：逐行翻、按原文缓存，翻过就不再翻；讲话整段翻。
> - v2：整首交给模型重写，追求画面感，加了「核心句要有高度」「俚语译出所指」「定稿译法」。
>
> 问题：
> - v1 平淡、直译、前后不连贯；
> - v2 偶尔加原文没有的意思（「Ah-ah-ah」→「念念不忘」）；
> - 俚语、核心句全靠提示词里的几条例子；
> - 你改过的句子只能手动加进 `zh_fixed.json`；
> - 没有检查，翻得好不好只能靠你一句句看。
>
> **目标**：一条完整的翻译流水线，所有歌共用。歌曲理解、术语、初译、润色、审校、人工定稿各司其职，每一步的结果都能在审核页看到、能改，改了之后只重跑受影响的部分。

## 1. 总流程

```
 精校好的字幕（v3）+ Genius 全文 + 歌曲信息（歌名、歌手、语种、现场 / 录音室）
        │
        ▼
 ┌─ 第 0 步 整理 ─────────────────────────────────────────────┐
 │ 每行标类型：歌词 / 讲话 / 现场改词 / 按顺序填的 / 纯语气词          │
 │ 断句分组：一句话被切成几行的，合成一组（翻译按组理解、按行输出）       │
 │ 去重：同一句歌词（副歌）只翻一次，所有出现的地方共用                 │
 └──────────────────────────┬────────────────────────────────┘
                            ▼
 ┌─ 第 1 步 歌曲理解（每首一次，可人工改）────────────────────────┐
 │ 输入：Genius 全文 + 歌曲信息                                     │
 │ 输出：主题、叙事视角（谁对谁说）、语气、核心句、                    │
 │      难点表（俚语 / 双关 / 比喻 / 典故：原文 = 所指 → 建议译法）、     │
 │      人名地名品牌表                                              │
 └──────────────────────────┬────────────────────────────────┘
                            ▼
 ┌─ 第 2 步 术语表（三层，优先级从高到低）────────────────────────┐
 │ ① 你定稿的句子（某一句就要这么译）                                 │
 │ ② 本首的术语 / 难点（第 1 步产出，可人工改）                        │
 │ ③ 全局规则和术语（所有歌：Shakira→夏奇拉、不用「妞」、结巴重复规则、品牌）│
 └──────────────────────────┬────────────────────────────────┘
                            ▼
 ┌─ 第 3 步 初译（准确）→ 中文 v1 ────────────────────────────┐
 │ 整首按顺序、按组翻；一组一组理解、按行输出                          │
 │ 要求：意思准、不漏、不加；俚语按难点表；专名按术语表                   │
 └──────────────────────────┬────────────────────────────────┘
                            ▼
 ┌─ 第 4 步 润色（表现力）→ 中文 v2（视频默认用这版）───────────────┐
 │ 以初译为准做改写：画面感、节奏、押韵；核心句要有高度；                 │
 │ 不能改变意思（第 5 步会对照初译检查）                               │
 └──────────────────────────┬────────────────────────────────┘
                            ▼
 ┌─ 第 4.5 步 顶部注释（画面顶部的「注：…」）──────────────────────┐
 │ 从歌曲理解的难点表里挑「翻译讲不透」的：双关、背景知识、真实人物事件      │
 │ 每首 3~6 条，每条 ≤ 25 字，跟着对应那句出现                          │
 └──────────────────────────┬────────────────────────────────┘
                            ▼
 ┌─ 第 5 步 审校（另一次独立调用，当「挑错的人」）────────────────────┐
 │ 逐行对照原文、初译、润色稿，找问题：                                 │
 │   意思跑偏 / 加了原文没有的 / 俚语按字面 / 前后不一致 / 太长 /         │
 │   夹外文 / 语气词被翻 / 讲话写成歌词腔                              │
 │ 输出：每个问题 = 哪一行、什么问题、建议改成什么                        │
 └──────────────────────────┬────────────────────────────────┘
                            ▼
 ┌─ 第 6 步 定稿 ─────────────────────────────────────────────┐
 │ 程序规则（一定执行）：你定稿的句子替换、纯语气词留空、去句号、           │
 │   歌词加 ♪ 讲话不加、长度检查                                       │
 │ 审校的建议：客观问题（太长、夹外文、「妞」、语气词）自动采纳；            │
 │   意思上的问题不自动改，在审核页标「翻译可疑」，你决定                   │
 └──────────────────────────┬────────────────────────────────┘
                            ▼
 ┌─ 第 7 步 人工审核（审核页）────────────────────────────────┐
 │ 看：歌曲理解、难点表、每行 原文 / v2 / v1 / 审校意见                 │
 │ 改：直接改某一行 → 存进「定稿」（选：只这首 / 所有歌）               │
 │     改难点表里某个词的译法 → 存进本首术语                            │
 │ 改完只重跑受影响的：改了哪组，就重译那一组和它前后一组（保持连贯）        │
 └─────────────────────────────────────────────────────────┘
```

## 2. 各步说明

### 第 0 步 整理

| 类型 | 怎么翻 |
|---|---|
| 歌词（对上 Genius） | 正常翻 |
| 按顺序填的（识别走样，用的 Genius 原文） | 正常翻 |
| 现场改词 / 现场加的内容 | 正常翻，告诉模型「这是现场即兴」 |
| 讲话 | 口语，不加 ♪，连续的讲话整段理解 |
| 纯语气词（Oh-oh、uh-uh） | 不翻，留空 |
| 片头歌名 | 单独翻（歌名有通行译名用通行的） |

- **断句分组：** 相邻两行之间停顿短、上一行没有句末标点，就算同一句（例：「Sorry, baby, hace rato / Que yo debí botar ese gato」）。
- **去重：** 读音一样的歌词行只翻一次。副歌每次出现的译法都一样，也省调用。

### 第 1 步 歌曲理解

输出 JSON，存成本首的 `translation/brief.json`，审核页能看、能改：

```
{
  "theme": "这首歌讲什么（2~3 句）",
  "voice": "谁对谁说：Shakira 对前任皮克",
  "tone": "讽刺、解气、居高临下",
  "core_lines": ["Las mujeres ya no lloran, las mujeres facturan", ...],
  "notes": [ {"src": "botar ese gato", "means": "gato = 不值得的男人，指前任", "zh": "把那个渣男扫地出门"}, ... ],
  "names": {"Clara": "克拉拉（双关：清楚）", "Hacienda": "税务局"}
}
```

只依赖 Genius 全文和歌名歌手：字幕变了不用重跑，歌词换版本才重跑。

### 第 3 步 初译、第 4 步 润色

| | 初译（v1） | 润色（v2） |
|---|---|---|
| 目标 | 准：不漏、不加、不错 | 好：画面感、节奏、核心句有高度 |
| 输入 | 字幕组 + 歌曲理解 + 术语表 | 初译 + 字幕组 + 歌曲理解 + 术语表 |
| 模型 | deepseek-v4-pro，思考 high | deepseek-flash（v4.1 flash），思考 high |
| 长度 | 不限（准确优先） | 每行 ≤ 18 字 |

**为什么分两步：** 现在 v2 一步同时追求「准」和「好」，偶尔为了好看加意思。分开后，润色以初译为底稿，审校时有对照。

### 第 4.5 步 顶部注释

字幕组常用的「注」：翻译一句话讲不透的双关、文化背景、真实人物事件，在画面顶部给一行小字说明。

| 项目 | 规则 |
|---|---|
| 注什么 | 只注翻译讲不透的：双关（Clara =「清楚」）、需要背景才懂的（Twingo 是雷诺的廉价小车、卡西欧是平价表）、真实人物事件（新女友 22 岁、西班牙税务局欠税案）。翻译已经说清楚的俚语（gato → 渣男）不注 |
| 数量 | 每首 3~6 条 |
| 写法 | 一行，≤ 25 字，以「注：」开头，只陈述事实，不评价 |
| 位置、样式 | 画面顶部居中，小字，浅灰色、半透明底条，和底部字幕区分开 |
| 时间 | 跟着对应那句出现，至少显示 4 s；同一个梗在歌里出现多次，只注第一次 |
| 避让 | 不压左上角 logo；注释显示期间，中间水印不放在顶部居中 |

例（BZRP）：

| 句子 | 注释 |
|---|---|
| Tiene nombre de persona buena / Claramente no es como suena | 注：新女友名叫 Clara，西语意为「清白、明亮」 |
| Cambiaste un Ferrari por un Twingo | 注：Twingo 是雷诺的廉价小车 |
| Yo valgo por dos de 22 | 注：皮克的新女友当时 22 岁 |
| Con la prensa en la puerta y la deuda en Hacienda | 注：Shakira 曾被西班牙税务局追缴欠税 |

注释写进字幕文件（单独的 Note 样式），审核页预览也显示；审核页能删、能改。

### 第 5 步 审校

- **独立调用：** 不让润色的那次调用自己检查自己。
- **输入：** 原文、初译、润色稿、歌曲理解。
- **输出：** 问题清单。

| 问题类型 | 处理 |
|---|---|
| 太长（> 18 字）、夹外文、用了「妞」、语气词被译成「哦 / 耶 / 啊」 | 自动采纳建议 |
| 意思跑偏、加了原文没有的、俚语按字面、前后不一致、讲话写成歌词腔 | 不自动改，审核页标「翻译可疑」，鼠标停上去看审校意见和建议译法 |

### 第 6 步 定稿规则（程序，不靠模型）

1. 你定稿的句子：原样替换。
2. 纯语气词行：中文留空。
3. 句末句号去掉（保留 ？！…）。
4. 歌词加 ♪，讲话不加。
5. 专名表里的外文名：如果中文里还夹着原文，替换成译名。

### 第 7 步 人工审核和定稿

审核页每行显示：原文 / 中文 v2 / 中文 v1 / 审校意见。

- **改一行：** 点中文 v2 直接改 → 保存时选「只这首」或「所有歌都这么译」。
  - 只这首 → 本首定稿表；
  - 所有歌 → 全局定稿表。
  - 这一点和你说过的「不要手动调整」不矛盾：这是定稿翻译，不是调字幕时间。如果你不想在页面上改，也可以只在页面上标问题，由我来改。
- **改难点表：** 改某个俚语的译法 → 本首术语，重跑用到它的那些组。
- **重跑范围：** 改了哪组，就重译哪组，再加前后各一组的润色（保持连贯），其他不动。

## 3. 缓存和版本

| 缓存 | 依赖 | 什么时候失效 |
|---|---|---|
| 歌曲理解 | Genius 全文、歌名歌手、提示词版本 | 歌词换版本、提示词改了 |
| 初译 | 这一组的原文 + 歌曲理解 + 术语表 + 提示词版本 + 模型 | 任意一项变了，只重译这一组 |
| 润色 | 初译 + 这一组 + 前后一组 + 歌曲理解 + 术语表 + 提示词版本 + 模型 | 同上 |
| 审校 | 原文 + 初译 + 润色 | 同上 |
| 顶部注释 | 歌曲理解 + 字幕 | 歌曲理解或对应的句子变了 |

- 每行都记录来源：哪个模型、哪一版提示词、有没有被审校改过、是不是你定稿的。
- 现在的 v1 缓存（zh_cache.json，按单行原文）和 v2 缓存（zh2.json，按整首）都换成按组缓存。

## 4. 检查项（自动）

每次翻完跑一遍，和字幕的回归检查一样：

| 检查 | 例子 |
|---|---|
| 你定稿的句子一字不差 | 「女人不再流泪，女人要为自己买单！」 |
| 禁用词 | 「妞」；语气词译成「哦 / 耶」；按字面翻俚语（「那只猫」） |
| 专名 | 法拉利、雷诺、劳力士、卡西欧、夏奇拉；中文里不夹原文 |
| 长度 | v2 每行 ≤ 18 字 |
| 一致 | 同一句副歌所有出现的地方译法一样 |
| 不漏 | 有内容的行（读音 ≥ 8 字）中文不为空 |

## 5. 调用量和时间（每首）

| 步骤 | 调用 | 时间（估） |
|---|---|---|
| 歌曲理解 | 1 次（有缓存就 0） | 20~40 s（pro） |
| 初译 | 1~2 次（长歌分两批） | 30~60 s（pro） |
| 润色 | 1 次 | 10 s（flash） |
| 审校 | 1 次 | 10 s（flash） |
| 合计 | 3~5 次 | 约 1~2 分钟 |

## 6. 需要你定的

1. 初译用 deepseek-v4-pro（准、慢），润色和审校用 deepseek-flash（快），这样分可以吗？
2. 审校发现「意思上的问题」：只标出来给你看，还是也自动采纳？我建议只标出来。
3. 你改过的译法，默认存成「只这首」还是「所有歌」？我建议默认只这首，专名类的（人名、品牌）存成所有歌。
4. 审核页要不要能直接改中文？还是你标出问题、由我来改？
5. 顶部注释：每首 3~6 条、顶部居中小字浅灰半透明底条，可以吗？

## 7. 实施步骤

| 步骤 | 内容 |
|---|---|
| 1 | 第 0 步整理 + 第 1 步歌曲理解（审核页能看歌曲理解和难点表） |
| 2 | 第 2 步术语表三层 + 第 3 步初译（按组）+ 第 4 步润色 |
| 3 | 第 4.5 步顶部注释 + 第 5 步审校 + 第 6 步定稿规则 + 第 4 节检查项 |
| 4 | 审核页：审校意见、「翻译可疑」标记、（如果要）直接改中文 |
| 5 | 先在这 4 首（5 个版本）上跑，你对比新旧翻译后再决定是否推广 |
