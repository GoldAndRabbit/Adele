## 1. 设计原则

1. **一次全局决策，不做局部修补。** 「这段声音唱的是哪一句」在一次整首的计算里决定，不再一小段一小段单独决定、再用规则修。
2. **互相校准。** 几种证据各有盲区，先找它们一致、最可靠的地方（锚点），再用锚点去约束不确定的地方，一轮一轮收敛。
3. **只有一个置信度。** 「这一行可不可信」用同一个公式算，不再拆成十几条各自带阈值的规则。
4. **参数全部共用。** 6～8 个参数，用一套覆盖各种类型的测试集统一定，不按歌调。
5. **决策和显示分开。** 分行、提前量、颜色、标注只影响显示，不影响对齐结果。
6. **听到什么出什么，补的要说明。** 用 Genius 原文替换识别出来的走样文字时，表格里标出来，写清依据。

## 2. 证据：各自擅长什么、盲区在哪

| 证据 | 擅长 | 盲区 |
|---|---|---|
| Genius 歌词 | 文字正确、句子顺序、段落结构（副歌在哪重复） | 现场改动（删段、换序、多唱几遍、即兴、对话）；换行和现场分句不一定一样（日语尤其明显） |
| 多遍整段识别（qwen-audio-3.1-asr-flash） | 现场实际唱了什么、什么时候唱、每个词的时间 | 听错（观众合唱、咬字含糊）、整段丢、复读上一句、对截取起止极敏感 |
| 声学强制对齐（MMS） | 已知文字时，时间很准（拉丁字母） | 不能判断唱的是哪句；日文不准 |
| 人声能量、音高曲线 | 哪里有人在发声、哪里是停顿；说话还是唱 | 观众声、混响会干扰；单独用分不准 |
| 立体声（左右声道相关性） | 观众合唱（现场环境话筒收的，左右差别大） | 每首歌混音不同，只能和本首比 |
| 节拍 / 小节 | 歌词按小节成句，适合当切点 | 说唱、自由节奏的段落不明显 |

**互相校准的方式：**

- **Genius ⇄ 识别：** Genius 纠正识别听错的词，按顺序补识别漏掉的句子；识别决定现场实际唱了哪几段、重复了几遍、哪里在说话。
- **识别 ⇄ 识别：** 多遍在同一时间听到同一句，可信；只有一遍有的，可疑。
- **识别 ⇄ 声学：** 识别给出文字和大致位置，MMS 在这个范围里定精确时间；MMS 对不上，说明位置或文字有问题。
- **锚点 ⇄ 锚点之间：** 两个可信锚点之间该唱哪几句、从哪里切音频重新识别，都由锚点决定。

### 3.1 和 v2 的区别

**v2 流程**（一段一段单独决定，再用规则修）：

```
 人声
  │
  ▼
 固定间隔切块（每 60 s，错开 0/30/15 s）× 3 遍识别
  │
  ▼
 每 8 s 挑一遍（Genius 词最多的那遍）──► 只剩一条词序列（另外两遍的信息丢了）
  │
  ▼
 按标点 / 停顿切短语 → 动态规划把短语拼成组 → 每组单独对 Genius 某一整行（≥ 70 分）
  │                                         （不知道上下文，不知道唱到第几段）
  ▼
 ┌──────────── 补丁（按顺序执行，每条只看局部）────────────┐
 │ 半句 / 前半句 / 两行连唱 / 唱两遍拆行                     │
 │ Genius 里没有的行：另一遍也听到才算                        │
 │ 每行回到三遍里找位置 → 5 个来源投票定时间                   │
 │ 句首语气词往前补                                         │
 │ 查漏：两遍都听到的补进来                                   │
 │ 歌词范围：连续 3 行才算 → 零星匹配去掉 → 周围像歌词又保留     │
 │ 同一句多次出现，取上一行之后那次                           │
 │ 按 Genius 顺序补缺的句子 → 识别复读改成下一句               │
 │ 讲话：歌词前后 + 音高 + 像歌词不算 + 开头块对话              │
 └────────────────────────────────────────────────────┘
  │
  ▼
 显示（分行、提前量）
```

**v3 流程**（一次全局决策，锚点互相校准）：

```
 人声 + 音高 / 节拍
  │
  ▼
 按自然停顿切块（人声停顿、段落边界、小节起点），几组互不相同的切法 × 多遍识别
  │
  ▼
 词网格：所有遍的所有词都保留
  │
  ▼
 整首顺序对齐：Genius 全部词 ⇄ 词网格，一次动态规划
 （下一个词 / 下一行 / 重复 / 跳回段首 / 跳过 / 歌词外，都在同一次计算里）
  │
  ▼
 锚点（一个置信度公式）──► 锚点之间的区间：在停顿处重新切、重新识别、MMS、小范围对齐
  ▲                                    │
  └────────── 新锚点（2~3 轮收敛）◄─────┘
  │
  ▼
 歌词外段落：一个判断（讲话 / 不出字幕）
  │
  ▼
 时间投票、显示
```

**主要区别：**

| | v2 | v3 |
|---|---|---|
| 切块 | 固定间隔，切点可能落在词中间；两遍可能切成一样 | 按自然停顿，保证每遍切法不同 |
| 三遍识别怎么用 | 每 8 s 挑一遍，另外两遍丢掉，后面再回去找 | 全部保留在词网格里，对齐时选最像的，并记下几遍支持 |
| 决定「唱的是哪句」 | 一组一组单独对 Genius 整行，不知道上下文 | 整首一次顺序对齐，知道唱到哪了 |
| 对齐的单位 | 行（要先把识别词分组） | 词（行的边界是结果，不用先分组） |
| 顺序、重复、第几次出现 | 事后用规则修（第 13、14、15 条） | 对齐时由跳转决定 |
| 观众合唱 / 识别走样 | 对不上 → 规则按顺序补 | 锚点之间按顺序，区间里重新识别 |
| 识别整段漏掉 | 空洞补识别（固定窗口试 12 次） | 锚点之间在停顿处重新切，已知该唱哪几句 |
| 可信度 | 十几条规则各有阈值（连续 3 行、≥ 85 分、两遍听到…） | 一个置信度公式 |
| 讲话 | 6 条规则 | 一个判断 |
| 规则 / 参数 | 34 条规则、二十多个阈值 | 约 10 条规则、7 个参数 |
| 改一处的影响 | 规则互相影响，改好一首可能改坏另一首 | 只调共用参数，用全部检查项验证 |

**不变的部分：** 识别模型（qwen-audio-3.1-asr-flash）、按语言的读音比对、多遍 + MMS 投票定时间、讲话用黄色、唱法标注、翻译、审核页、显示规则。

## 4. 第 0 步：听

### 4.1 找自然停顿（候选切点）

整首扫一遍，找出所有可以切的地方，每个打一个分：

| 特征 | 怎么算 | 说明 |
|---|---|---|
| 人声停顿 | 人声能量低于本首参考值，且音高曲线显示没有在发声，持续 ≥ 0.4 s | 保证不切在词中间、长音中间 |
| 停顿长度 | 越长分越高 | 长停顿多半是句子或段落之间 |
| 段落边界 | 连续 ≥ 4 s 没有人声（伴奏、间奏） | 最好的切点 |
| 小节起点 | 节拍检测，切点离小节起点越近分越高 | 歌词一般按 4 / 8 小节成句 |

只用到现在已经算好的东西（人声音频、音高曲线），再加一个节拍检测（librosa，本地，很快）。

### 4.2 选出几组互不相同的切法

- 每组把整首切成 25～60 s 的块，只在候选切点处切。
- 第一组优先用分最高的切点；后面每组**刻意避开前面已经用过的切点**，保证每一遍的上下文真的不同。
- 遍数由第 12 节的实验决定（3、5、7 遍对比）。

### 4.3 识别

- 每组每块送 qwen-audio-3.1-asr-flash，拿到字级时间戳；日中韩每个分块单独算一个词；异常长的词修正起点（附录 B）。
- 结果按「音频内容」缓存，同一段音频不重复调用。

### 4.4 输出

- **词网格：** 所有遍的所有词，带时间、来自哪遍。不在这一步挑「用哪一遍」。
- **整首曲线**（缓存）：音高稳定度、立体声相关性、人声能量。

## 5. 第 1 步：整首顺序对齐

### 5.1 Genius 侧

- 按顺序展开成词序列。每个词带行号、段落号：有 `[Chorus]`、`[Verse]` 等标记就用标记；没有就把 Genius 里重复出现的几行归成同一段落。
- 每个词转成按语言的读音，用于比相似度：
  - 日语：转假名，按字比；不看 Genius 的换行。
  - 西语：同音字合并（v / b、z / s、ll / y、c / k / s）。
  - 意大利语、英语、葡语、法语：各自的规则（v2 已有）。
  - 每一行的语言用逐行语言识别（v2 已有）。
- 括号里的和声（`(Oh-eh)`）、纯语气词，标为「可选」：唱了可以对上，没唱跳过不扣分。

### 5.2 识别侧

- 词网格按时间排序。同一时刻不同遍听到的词不一样时都是候选，对齐时选最像的那个，并记下有几遍支持。

### 5.3 状态和跳转

状态：「Genius 第 i 行第 j 个词」，加一个「歌词外」状态。

| 跳转 | 代价 | 对应的现场情况 |
|---|---|---|
| 同一行下一个词 | 0 | 顺着唱 |
| 跳过本行一个词 | 小 | 没唱、没识别出来 |
| 跳过可选词（和声、语气词） | 0 | 和声常常听不到 |
| 行尾 → 下一行行首 | 0 | 顺着唱 |
| 行尾 → 本行行首 | 小 | 一句唱两遍 |
| 行尾 → 某个段首 | 中 | 副歌再唱、现场换序 |
| 跳过 k 行 | k × 中 | 现场删段 |
| 进入 / 留在歌词外（每个识别词） | 固定 | 讲话、喊声、即兴、幻听 |

### 5.4 得分

每个识别词和 Genius 词的读音相似度（0～1，按语言），加上跳转代价，动态规划找总分最高的路径。

### 5.5 输出

- 每次唱到的 Genius 行：行号、对上的词（各来自哪几遍）、起止时间、对上的词占这一行的比例。
- 歌词外的段落：时间范围、识别到的文字。

### 5.6 为什么按词对齐，而不是按行

按行对齐，要先决定「哪几个识别词算一组去对 Genius 的一行」。这一步是 v2 一大半规则的来源：停顿切短语、两行连唱、半句、唱两遍拆行、日语换行不一致。按词对齐不需要分组，行的边界是对齐出来的结果。

## 6. 第 2 步：锚点

### 6.1 置信度（一个公式）

对每一次唱到的 Genius 行：

```
置信度 = 文字   对上的词占这一行的比例 × 平均读音相似度
       × 遍数   有几遍识别在 ±0.5 s 内给出这一行（拉丁字母再看 MMS 是否一致）
       × 顺序   前后行在 Genius 里是不是相邻，或者是合理的段落跳转
       × 独特   这句在 Genius 里只出现一次为 1；重复出现的句子低一些，要靠前后行确定是第几次
```

高于锚点阈值的行就是锚点。

### 6.2 不用算的锚点

- 连续 ≥ 4 s 没人声的地方（伴奏、间奏、段落之间）；
- 整首的开头和结尾。

### 6.3 这个公式替代了 v2 的哪些规则

连续 3 行才算歌词范围、零星弱匹配去掉 / 保留、两遍听到才补漏、识别复读改下一句、同一句取第几次出现……这些都是「这一行可不可信」的不同侧面，现在合成一个数。

## 7. 第 3 步：锚点之间逐段校准

两个相邻锚点之间是一个区间。已知它的**时间范围**，以及 Genius 里两个锚点之间**应该唱哪几句**（可能是 0 句）。

### 7.1 三种区间

| 区间 | 例子 | 做什么 |
|---|---|---|
| 应该有句子，识别也有内容，但没对准 | BZRP 4:38「La suegra y la vecina」（该唱 Con la prensa…）、4:46「Más dura」（该唱 Las mujeres…）、5:00「A ti te quedará / Por suerte」 | 区间里小范围顺序对齐，只能是这几句或歌词外；文字走样、但顺序确定，就用 Genius 原文 |
| 应该有句子，识别几乎是空的 | BZRP 3:31～3:55（几遍都漏） | 在区间两端的自然停顿处重新切，多个起止识别；拉丁字母用 MMS 把应该有的句子在区间里强制对齐，声学合得上才放进字幕 |
| 不应该有句子 | Lose Yourself 开场 / 结尾致谢、そばにいるね 开头对话 | 交给第 4 步 |

### 7.2 为什么能解决「对截取起止敏感」

- 现在是固定间隔切块，切点可能落在词中间或者含糊的地方。
- 区间两端是锚点，切点选在锚点处的自然停顿上，是真正的句子 / 段落边界。
- 区间短（通常 5～30 s），而且已知这里该唱哪几句，可以挑和这几句最像的那次识别结果。

### 7.3 收敛

每一轮新增的高置信行变成新锚点，区间变小、变少。没有新锚点就停，最多 3 轮。

### 7.4 用 Genius 原文替换走样文字时的边界

- 只在两侧都有锚点、且这几句在 Genius 里正好夹在两个锚点之间时替换。
- 如果区间里有声音、但对不上任何一句，又不像讲话，就**不硬塞**歌词，判定列标「漏」。
- 表格里写清依据：上一个锚点是哪句、下一个锚点是哪句、这里听到的是什么。

## 8. 第 4 步：歌词外的段落

### 8.1 判断哪些段落

- 第 1 / 3 步对齐到「歌词外」的段落；
- 开头 / 结尾单独的一块（和后面隔着 ≥ 6 s 伴奏），整块音高一直在滑，即使 Genius 收录了（そばにいるね 开头对话就是这种）。

### 8.2 一个判断

| 结果 | 条件 |
|---|---|
| 讲话（黄色字幕，中文不加 ♪） | 至少两遍识别听到相近的话，且音高一直在滑 |
| 不出字幕 | 其余：喊声、单个词、只有一遍听到的（多半是幻听） |

讲话连续几行一起翻译，中文可以跨行调整语序（v2 已有）。

### 8.3 唱法标注（只标注，不影响字幕）

唱 / 说唱 / 讲话 / 观众合唱?，用音高稳定度、语速、立体声（v2 已有），只显示在审核页的「唱法」列。

## 9. 第 5 步：时间与显示

### 9.1 时间

- **开头：** 每一行对上的第一个词，各遍各给一个时间，拉丁字母加 MMS；相差 ≤ 0.5 s 的算一伙，取人数最多的一伙。
- **结尾：** 对上的最后一个词。
- **句首没对上的 Genius 词**（拖腔的语气词）：按平均每词时长往前推，不越过上一行。

### 9.2 显示

- 一行最多 8 词（日中韩 16 字）；超过 12 词在最靠中间的逗号处拆；语气词尾巴留在原行。
- 提前 0.2 s、停留 0.4 s、最短显示 0.8 s；审核页可以即时切换「提前 0.8s / 不提前」预览。
- 括号配对；整行包在括号里的去掉外层。
- 纯语气词行中文留空。

### 9.3 审核页表格

时间、语言（国旗）、唱法、Genius 原句、识别结果、校准字幕、判定、中文。

判定的取值：

| 判定 | 含义 |
|---|---|
| ✓ | 锚点 |
| 校 | 区间校准后确定 |
| 顺序 | 用 Genius 原文替换走样文字 |
| 黄 | 时间各来源不一致 |
| 漏 | 有人声、没字幕 |
| 未确认 | 歌词外、不出字幕 |

鼠标停在判定上，看依据。

## 14. 风险和应对

| 风险 | 应对 |
|---|---|
| 顺序对齐把讲话里一个像歌词的词拉进歌词 | 进出歌词外有代价，单个词不值得；置信度低也不会成为锚点 |
| 现场换序很大（串烧、即兴改编），顺序先验反而误导 | 「跳回段首 / 跳过 k 行」允许任意跳转，只是有代价；识别证据强时会跳 |
| 用 Genius 原文替换走样文字，替换错了 | 只在两侧都有锚点、句子正好夹在中间时替换；表格标「顺序」并写依据，方便审核 |
| 第 3 步重新识别次数多、慢 | 只对不确定的区间做；结果缓存；最多 3 轮 |
| 歌词版本和现场不一致（Genius 收的是录音室版或另一个版本） | 对不上的部分走歌词外；第 1 步统计「歌词外比例」，超过一半时在审核页提示「歌词版本可能不对」 |
| 参数在这 5 个版本上调得过拟合 | 参数少（7 个）；之后用其他歌验证、不再调参数 |

## 16. 附录 B：这几天发现的识别模型特性

方案里的很多设计是针对这些特性的：

| 特性 | 例子 | 方案里怎么应对 |
|---|---|---|
| 语种参数无效 | 传意大利语、传错成日语，结果完全一样 | 不传；事后按逐行语言选读音规则 |
| 意大利语没有标点 | 整段连成一句 | 按词对齐，不依赖标点 |
| 长段里会把含糊的一整段丢掉 | BZRP 3:31～3:55 三遍全空，单截 35 s 能听出来 | 按自然停顿切、多组切法；区间校准时短段重新识别 |
| 对截取起止极敏感 | 起点 205.98 返回空，206.0 返回整句 | 切在自然停顿上；同一区间多试几个起止 |
| 会复读上一句 | BZRP 3:08 第二遍又听到一遍「¿Quién es Nombre la persona buena」 | 顺序对齐：复读的词对不上下一句 |

| 个别词时间戳异常长 | Perdón 被标成 29.9～42.2 s | 超过 3 s 的词起点修正 |
| 观众合唱听成走样的文字 | 「Ella arrastraba la vecina」= Me dejaste de vecina | 锚点之间按顺序用 Genius 原文 |
