## 0. 一句话

**先让 Qwen 完整听出「唱了什么」，再用文本匹配对上 Genius，最后由多个引擎各自给出「什么时候唱」，结果全部打出来对比，一致的直接用，不一致的标出来给人看。**
不再有「猜每 2.5 s 是哪句 + 12 步规则补漏改错」。

## 1. 已经确认的事实

| # | 事实 | 怎么确认的 |
|---|---|---|
| 1 | Qwen 一次听整首，比切成小块听准得多 | GIRL LIKE ME 整首一次：两遍 So they tell me 都在、报国家名一个不漏、自己按语气断好了句；同一段切成 30 s 只认出一句；切成 2.5 s / 6 s / 12 s 会漏词、把连唱两遍合成一遍、认错语种 |
| 2 | Genius 是录音室版，和现场不一样 | 删段、换序、重复、改词（报国家名）、口号 |
| 3 | MMS 只能定时间，不能判断唱的是哪句 | 在这场的人声上，唱对的句子和配错的句子声学分数分不开（见根因分析 2.7） |
| 4 | 一条一条加规则，修好一处坏一处 | 这两天加了 12 步修补，阈值都是看着某一首的某一处定的 |
| 5 | 现在用的 `qwen3-asr-flash`（OpenAI 兼容接口）只返回文字、不返回时间 | 阿里云文档 |
| 6 | 阿里云有更新的模型直接返回时间戳 | `qwen-audio-3.1-asr-flash`（同步，≤5 分钟，时间戳固定返回）；`*-filetrans` 版本（异步，≤12 小时，句级 + 字级时间戳，要公网 URL） |

### 名词

| 名词 | 是什么 |
|---|---|
| Qwen ASR | 阿里云百炼的语音识别接口：给一段声音，返回识别出的文字（新模型还返回时间） |
| Genius 原句 | 歌词网站上的歌词（录音室版） |
| MMS | Meta 开源的语音对齐模型（Massively Multilingual Speech），本地跑：给一段声音和**已知的文字**，算出每个词在什么时候唱；它不负责听出唱了什么 |
| 窗口识别 | 把人声切成很短的一段一段（现在是 2.5 s，每 0.5 s 一段）分别送 Qwen；每段文字自带「这是第几秒」 |
| 文本匹配 | 比两段文字像不像。按读音比（Shak, shak ≈ Sha-Sha-Shakira、Sangaleva ≈ zangalewa），不按拼写比 |

## 3. 文本匹配 ①：每行显示什么字（步骤 3）

```
 Qwen 整段识别的一句                    Genius 歌词（全部句子）
 ─────────────────────                ───────────────────────────
 "Shak, shak, shak it up"   ──比读音──►  Sha-Sha-Shakira, Sha-Sha-Shakira   78 分
                                        Electric field, so shock me        41 分
                                        ...
                              │
            ┌─────────────────┼──────────────────────────┬─────────────────────────┐
            ▼                 ▼                          ▼                         ▼
     像一句（≥ 70 分）    像连续两句（≥ 70 分）      都不像（< 70 分）         一句话很短 / 纯语气词
     → 显示 Genius 原句   → 拆成两行，各显示         → 现场改词 / 即兴         → 只和读音相同的语气词配
                            Genius 原句                显示 Qwen 的文字           （oh ↔ oh，hey ≠ ayy）
                                                       （报国家名就是这种）
```

- 同一句歌词在 Genius 里出现好几次（副歌）：选「接着上一行往下唱」的那一处
- 比的是读音不是拼写：z/s、v/b/w、ll/y、c/k 当成一样；去掉重音符号
- 每行都记下：对上的 Genius 原句、相似度分数（审核页「校准策略」列显示）

## 4. 三个时间引擎和合并规则（步骤 4、5）

### 4.1 三个引擎各自怎么定时间

```
 ┌───────────────────────────────────────────────────────────────────────────────┐
 │ 引擎 A：Qwen 自带时间戳（换新模型才有）                                          │
 │   整段识别时直接返回每句 / 每个词的开始结束时间                                    │
 │   优点：和文字同一次识别，最省事        缺点：歌唱场景准不准未知，要实测           │
 ├───────────────────────────────────────────────────────────────────────────────┤
 │ 引擎 B：文本匹配 ②（N 行 ↔ 窗口文字）                                            │
 │                                                                               │
 │   时间轴 ─────────────────────────────────────────────────────────►           │
 │   窗口    [w1][w2][w3][w4][w5][w6][w7][w8][w9] ...（每段文字自带时间）          │
 │   第 1 行  ████████████                                                       │
 │   第 2 行              ███████████                                            │
 │   第 3 行                         █████████████                               │
 │                                                                               │
 │   按顺序单调对齐：第 i 行只能在第 i-1 行之后                                     │
 │   开始 = 最早听到这行开头几个词的窗口；结束 = 最后听到这行末尾几个词的窗口          │
 │   优点：只靠文字，不受伴奏声学影响        缺点：精度约 ±0.5 s                     │
 ├───────────────────────────────────────────────────────────────────────────────┤
 │ 引擎 C：MMS 声学对齐                                                            │
 │   N 行文字按顺序一次性对齐到整首人声（v1 refine_timing 的做法）                    │
 │   每行之间放「*」吸收间奏、和声、喊话                                              │
 │   优点：精度高（约 ±0.1 s）              缺点：文字错了会被硬对上，伴奏重时会偏     │
 │   和 v1 的区别：v1 对的是 Genius 全部歌词（没唱的句子会把前后拖偏）；               │
 │               这里对的是实际唱了的 N 行，没有这个问题                              │
 └───────────────────────────────────────────────────────────────────────────────┘
```

## 5. 窗口长度（引擎 B 用）：2.5 s 合不合理

```
 2.5 s 窗口，每 0.5 s 一个（现在已有缓存）
 ─────────────────────────────────────────
 时间轴   0.0   0.5   1.0   1.5   2.0   2.5   3.0   3.5   4.0
 窗口1   [=========================]
 窗口2         [=========================]
 窗口3               [=========================]
 ...     每个时刻被 5 个窗口听到；每个窗口只装得下 3~6 个词
```

| 问题 | 老流程里的后果 | 新流程里还有没有 |
|---|---|---|
| 太短，两头常切在词中间 | Venezolana → Mezorana、Поттерана | 有，但影响小：只需要窗口里出现这行的**部分**词 |
| 人群声里幻听（哎呀、하나 둘 셋、Thank you） | 被当成字幕补进去 | 有，但影响小：窗口文字只用来找已知句子的位置，不会变成字幕 |
| 拖长音时一个窗口只有一个元音 | 认不出是哪句 | 有：这一行在引擎 B 里可能找不到，靠 A / C |
| 同一句唱两遍分不清第几遍 | 字幕跳来跳去 | 没有：顺序由整段识别定了，按顺序单调对齐 |
| 语种认错 | 整段乱码 | 有：auto 在短片段上常认错 |

结论：**新流程里可以用，但不一定最好**。实验时同时跑两种，按「和 MMS / Qwen 时间戳一致的比例」选：

```
 方案 B1：2.5 s，每 0.5 s   （已有缓存，不花钱）
 方案 B2：5 s，  每 1 s     （每首约 250~300 次 Qwen 调用；上下文多一倍，切词、幻听、认错语种少）
```

如果引擎 A（新模型自带时间戳）够准，引擎 B 可能只作为兜底。

## 6. Qwen 模型选择（先测再定）

| 模型 | 时间戳 | 单次上限 | 输入 | 备注 |
|---|---|---|---|---|
| `qwen3-asr-flash`（现在用的） | 不返回 | 5 分钟 / 10MB | 本地 / base64 | OpenAI 兼容接口 |
| `qwen-audio-3.1-asr-flash` | 固定返回 | 5 分钟 / 2GB | URL / base64 | 阿里云现在推荐的同步版（2026-07 发布的新一代） |
| `qwen-audio-3.1-asr-flash-filetrans` | 句级 + 字级 | 12 小时 / 2GB | 公网 URL，异步 | 推荐的录音文件版 |
| `qwen3-asr-flash-filetrans` | 句级；`enable_words` 出字级 | 12 小时 / 2GB | 公网 URL，异步 | |

- 文档说百炼支持「歌唱识别」，但没写是哪个模型、对伴奏和演唱会人声效果如何 → **必须实测**
- 新模型支持传「上下文」；能不能把 Genius 歌词当上下文：代码里记过「传歌词进去模型会照抄」，所以只作为对比项，不默认开
- 超过 5 分钟的歌（BZRP 5:18、Waka Waka 5:04）：同步版要在最安静处切成两段；filetrans 版要先把音频放到能公网访问的地址

### 实测结果（2026-10-18，GIRL LIKE ME 整首一次）

`qwen-audio-3.1-asr-flash` 走 DashScope 原生接口（`/api/v1/services/aigc/multimodal-generation/generation`，base64 音频），
响应里 `output.output.sentence.words[]` 是**字级时间戳**（`begin_time` / `end_time` 毫秒 + `punctuation`）。

| 已知点 | 原流程 / MMS | 新模型时间戳 | 差 |
|---|---|---|---|
| 0:37 第一句 So they tell me | 37.08 | 37.16 | 0.08 s |
| Venezolana / Ecuatoriana / Puertorriqueña / Dominicana | 98.04 / 100.0 / 101.88 / 103.78 | 98.04 / 100.08 / 101.88 / 103.96 | ≤ 0.2 s |
| Las argentinas / brasileras / bolivianas | 105.71 / 107.61 / 109.44 | 105.72 / 107.64 / 109.56 | ≤ 0.12 s |
| 1:00 you're lookin' for / A girl like me | 59.99 / 63.91 | looking 61.72 / a girl 64.26 | — |

| | qwen3-asr-flash（现在） | qwen-audio-3.1-asr-flash（新） |
|---|---|---|
| 时间戳 | 无 | 字级，和已知点差 ≤ 0.2 s |
| 报国家名 | 每个后面多一个 Latina，Dominicana 听成 Americana | 12 个全对 |
| 连唱两遍 | 都在 | 都在 |
| Sha-Sha-Shakira（1:23~1:30） | 听成 Shak, shak, shak it up | **整段漏了** |
| 其他 | — | glossy → plastic、bossy → boss（对 Genius 时会改回来） |

结论：**整段识别换成 `qwen-audio-3.1-asr-flash`，它的字级时间戳作为引擎 A**。它漏掉的段落（Sha-Sha-Shakira）按第 8 节第 1 条处理：单独再听一遍、在表格里列出来，不自动补进字幕。

### GIRL LIKE ME 实验结果（`workflow_v2/align3.py`，结果在 `songs/04_girl_like_me/exp/`）
