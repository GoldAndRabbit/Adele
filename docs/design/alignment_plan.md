> **版本名（2026-10-18 起）**：v0 = 原流程（13 步，正式字幕 `songs/<nn>/lyrics.*`）；v1 = 第一版实验（`asr_match.py`，写到 `exp/`）；

> 第二版根据实验里新发现的问题补了三块：**语言档案**、**三遍识别的时间投票**、**漏掉 / 两遍互证的处理**。

## 0. 一句话

**先弄清这首歌是什么语言；Qwen 整段听三遍，决定唱了什么；每行字幕在三遍里各找一次位置，加上窗口文本和 MMS，按语言选可信的几个来投票定时间；所有判断都打在表格里给人看。**

## 1. 已经确认的事实

| # | 事实 | 怎么确认的 |
|---|---|---|
| 1 | Qwen 听长段落（几十秒）比短切片准得多 | GIRL LIKE ME 整首一次：重复、报国家名全对；切成几秒的片段换哪个模型都会听错（Ecuatoriana → venezolana / Porto Alegre） |
| 2 | 太长（整首 4 分钟一次）也不行 | Dai Dai 整首一次：开头人群喊的乱码把后面带偏，首段主歌、3:10 西语句全漏；切成 ≤ 60 s 都识别出来 |
| 3 | 某一遍识别会整段漏掉，换个切点就听到了 | Dai Dai 0:35~1:10、BZRP 0:36~0:46 |
| 4 | **三遍识别给同一句的时间，大多数几乎一样；偶尔一遍跑偏，另外两遍一致** | 中位差 0.06 s；差 > 3 s 的：sobaniirune 5 句、Lose Yourself 3 句、HKT48 2 句；**和切点无关**（10 个里只有 2 个在切点附近） |
| 5 | 现在只信挑中的那一遍的时间，跑偏了没人纠正，另外两遍的正确时间反而被列成「漏掉的段落」 | sobaniirune 1:57（同一句出现两次：一行字幕在 2:02，一行「漏」在 1:57） |
| 6 | MMS 只能定时间，不能判断唱的是哪句；**对日文定时间也不准** | 演唱会人声上声学分数分不开对错句；日文几乎都落在搜索范围的边上（和 Qwen 时间差正好 2.0 s） |
| 7 | 后面各步都默认是拉丁字母的语言 | 读音规则是西语的、长度按空格数词、「不像词」按字母数；日文是临时补的罗马音 |
| 8 | Genius 是录音室版，和现场不一样 | 删段、换序、重复、改词、口号；还可能拿错语言版本（Waka Waka 有英 / 西两版） |
| 9 | 一条一条加规则，修好一处坏一处 | 第一轮 12 步修补的教训；现在每次改动都跑回归检查 |

### 名词

| 名词 | 是什么 |
|---|---|
| 整段识别 | 人声切成 ≤ 60 s 的段落送 `qwen-audio-3.1-asr-flash`，返回文字 + 每个字 / 词的时间 |
| 第一 / 二 / 三遍 | 同一首识别三遍，三遍的切点分别错开 0 / 30 / 15 s（每段都是长上下文，只是切的位置不同） |
| Genius 原句 | 歌词网站上的歌词（录音室版） |
| 窗口识别（B） | 2.5 s 一段、每 0.5 s 一段送 `qwen3-asr-flash` 的旧识别结果，每段自带时间；只有 Shakira 这场有 |
| MMS（C） | Meta 开源的语音对齐模型，本地跑：给声音和已知文字，算出每个词什么时候唱 |
| 读音比对 | 比两段文字读起来像不像（Shak, shak ≈ Sha-Sha-Shakira），按语言用不同规则 |

## 3. 语言档案（新增）

### 3.1 怎么得到

```
 Genius 歌词 ──► 逐句判断语言（文字类型 + 常见词）──┐
                                                  ├──► 语言档案
 三遍整段识别 ──► 每段识别出来是什么语言 ───────────┘     主语言、次要语言、文字类型
                                                         每句歌词的语言
                                                         「歌词版本和现场对不上」标记
```

- 已有的：Shakira 这场 lyrics 阶段记过 `song.json` 的 `lang` / `langs`；v1 单曲现在是手填的，改成同样自动判断
- 识别结果的语言和 Genius 歌词的语言对不上（现场唱英文版、Genius 拿的是西语版）→ 标「歌词版本可能不对」，这首先不硬对，表格里提示

### 3.2 按语言选做法

| 环节 | 拉丁字母（英 / 西 / 意 / 葡 / 法） | 日文 | 中文 | 韩文 |
|---|---|---|---|---|
| 识别时告诉模型语种 | 单语歌告诉；混唱歌不告诉 | 告诉 | 告诉 | 告诉 |
| 读音比对 | 按该语言规则（西：z/s、v/b、ll/y；意：ch/k、gn；英：按拼写） | 转罗马音 | 转拼音 | 转罗马字 |
| 长度怎么数 | 按词 | 按字（假名 + 汉字） | 按字 | 按字 |
| 一行最多 | 约 8 个词 | 约 16 个字 | 约 16 个字 | 约 16 个字 |
| 「太短、不像词」 | 3 个字母以上的词至少 2 个，或有 5 个字母以上的词 | 至少 3 个字 | 至少 2 个字 | 至少 3 个字 |
| 语气词表 | 各语言一份（英 oh / yeah，西 ay / eh） | ああ / ねえ… | 啊 / 哦… | 아 / 오… |
| 句首拖腔往前补 | 每个音节 0.35 s | 每个假名 0.2 s | 每个字 0.25 s | 每个字 0.25 s |
| MMS 参与投票 | 参与 | **不参与**（实测不准） | 不参与 | 不参与 |

- 混唱歌（Dai Dai 英语夹西语、Empire / Inevitable 英西串烧）：**逐句**按这句的语言选
- 「识别时告诉模型语种」需要先确认 `qwen-audio-3.1-asr-flash` 同步接口支持语种参数；不支持就都用自动识别，再用三遍识别的语种是否一致来核对

## 4. 三遍整段识别

| 规则 | 原因 |
|---|---|
| 每段 ≤ 60 s，在目标切点 ±15 s 内最安静的 1 s 切 | 太长会被开头的乱码带偏；太短听不准 |
| 三遍切点错开 0 / 30 / 15 s | 每一句至少有一遍是落在段落中间听的 |
| 单个词超过 3 s：起点取结束前 1 s | 个别词的起点会粘在上一个词结束处（Perdón 29.9~42.2） |
| 接口失败 / 断网自动重试；结果按音频缓存 | 重跑结果不变；要重新识别时删缓存 |

## 5. 定文字

```
 三遍识别 ──每 8 s 挑一遍（Genius 词最多）──► 一串词
     │
     ▼
 按逗号 / 句号 / 停顿 ≥ 0.4 s 切成短语；没标点又超过 6 个词的长串拆成一个词一段
     │
     ▼
 动态规划：短语怎么拼成字幕行总分最高
   一组短语（中间停顿 ≤ 1.5 s）对上一句 Genius（或一句唱了两句歌词，按词拆开）
       得分 =（读音相似度 − 60）× 词数
   对不上的短语单独成行，得 0 分；相邻的对不上的短语拼回一行，但一行不超过「一行最多」
     │
     ▼
 每行：像 Genius（≥ 70 分）→ 显示 Genius 原句；不像 → 显示识别文字（现场改词 / 即兴）
       Genius 里同一段唱两遍的句子（Sha-Sha-Shakira, Sha-Sha-Shakira）也和半句比
       Genius 里没有的行：另外两遍至少一遍也听到、且不是「太短、不像词」，才进字幕
```

## 6. 定时间：投票

### 6.1 每个来源怎么给时间

| 来源 | 怎么算 | 什么时候没有 |
|---|---|---|
| A1 / A2 / A3 | 在这一遍识别里找和这行读音最像的一串词（前后 15 s 内），取第一个词的开始时间 | 这一遍没听到这句 |
| B 窗口文本 | 这行开头几个词最早出现在哪几个 2.5 s 窗口 | 没有窗口识别（v1 单曲）；或这行太短 |
| C MMS | 这行文字在前后行之间强制对齐到人声，取第一个词的时间 | 这行不是拉丁字母（日 / 中 / 韩） |

### 6.2 投票规则

```
   第 i 行：A1、A2、A3、B、C 中有结果的几个时间
                      │
                      ▼
   相差 ≤ 0.5 s 的分成一伙，取人数最多的一伙（人数一样取含 C 的，再取含 A 的）
                      │
        ┌─────────────┴─────────────────────────┐
        ▼                                       ▼
   这伙 ≥ 2 个                               每个都单独一伙
   ✓ 用这伙里最精确的：                       标黄，用三遍识别（A1~A3）的中位数
     C（拉丁字母句）> 三遍识别的中位数 > B      五个时间都列出来
   被排除的来源在「校准策略」里写明             （只有一个来源时同样标黄）
   （例：第一遍差 4.9 s，没用）
                                              五个都没有 → 标红，不出字幕，表格里留着
```

- 结束时间：用同一伙里的结束时间（MMS 或识别给的末字结束）
- 投票后前后两行顺序颠倒的：按三遍识别的中位数重排，标黄

## 7. 查漏和补漏

| 情况 | 处理 | 表格里显示 |
|---|---|---|
| 有人声没字幕，听到的就是前后 10 s 内某行字幕 | 不是漏，是时间不一致，第 4 步已经投票处理 | 不单独列（只在那一行的策略里写「某遍时间差 X s」） |
| 至少两遍在同一位置（±1.5 s）听到同一句，且是 Genius 原句或通过「像词」检查 | **补进字幕**（两遍独立识别互证，可信度够） | 正常一行，判定标「补」，策略写「挑中的那遍漏了，另外两遍都听到」 |
| 只有一遍听到 | 不补 | 灰色「漏」，列出听到了什么 |
| Genius 里没有、另外两遍都没听到 / 太短不像词 | 不补 | 灰色「未确认」 |

（这一条改变了第一版「漏掉的只列不补」：第一版的「漏」里大部分其实是两遍都听到、只是挑中那遍没听到的句子，也有不少只是时间差，混在一起没法看。）

## 10. 按综合判断替你定的事（有不同意见随时改）

| # | 问题 | 定的做法 | 理由 |
|---|---|---|---|
| 1 | 要不要语言档案 | 要，整首 + 逐句都做，放在最前面 | 读音、长度、MMS 是否可信都依赖语言；混唱歌逐句不同 |
| 2 | 识别时告诉不告诉模型语种 | 单语歌告诉、混唱歌不告诉；先确认接口支持 | 告诉能少认错语种；混唱歌告诉了会把另一种语言认偏 |
| 3 | 挑中那遍漏了、另外两遍都听到的句子 | **补进字幕**，标「补」 | 两遍独立识别互证；这正是之前「漏」里最多的情况 |
| 4 | 日文 / 中文 / 韩文用不用 MMS | 不参与投票，只列出来 | 实测日文不准 |
| 5 | v1 单曲要不要补窗口识别（B） | 先不补 | 有三遍识别投票后，B 只是多一票；每首要多 500~600 次调用。投票结果里「标黄」还多再补 |
| 6 | 投票阈值 | 0.5 s 算一致 | 第一版实验：三遍识别中位差 0.06 s，0.5 s 足够宽 |

| 8 | 歌曲前后的说话 | 归为「讲话」：Genius 里没有、语速快（≥ 2.2 词 / 秒且 ≥ 8 词）或在第一句歌词之前 / 最后一句之后（≥ 5 词）；单独写 `exp_v2/speech.srt`，用黄色 Speech 样式，中文不加 ♪ | 和 v0 的讲话字幕统一 |
| 9 | 逐句语言标记 | 表格每行一列「语言」（英 / 西 / 意 / 日…）；单词句没有虚词时看字母和词尾（ñ、重音、-ana / -ción） | 混唱歌逐句不同；报国家名这种单词句之前会被判成整首的主语言 |

## 附录 B：第一版实验中的调整

| 发现的问题 | 调整 |
|---|---|
| 接口按子词给时间（Venez / ol / ana） | 前面带空格 / 只有空格的子词是词的分界 |
| 对 Genius 时长短差太多也算像（Dominicana ≈ I like dominicanas） | 去掉语气词和括号后比；长度比不在 0.6~1.7 之间直接判不像 |
| 整首 4 分钟一次识别大段漏掉 | 切成 ≤ 60 s |
| 短切片复核（任何模型）不可靠 | 去掉逐句复核；改成三遍整段识别 |
| 某一遍整段漏掉 | 每 8 s 从三遍里挑 |
| 开场口号乱码（If apa / If ini） | 另外两遍也听到才进字幕；太短不像词的不进 |
| 识别结果整段连成一句（Sarà perché ti amo 2023 版、圣雷莫串烧一整屏） | 短语 + 动态规划；没标点的长串拆成一个词一段；对不上的一行不超过 8 个词 |
| 句首拖腔语气词识别不出（Ah-ah-ah 晚 1 s） | 开头往前补 |
| MMS 整首一次对齐被开头没唱歌的人声带偏 | 每行在自己附近对齐 |
