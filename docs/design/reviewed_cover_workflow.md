# 封面选帧、试排与发布

每首歌从自己的原片时间段选帧。先比较至少三个时间点的原片与四版带字试排，保留时间码、原帧摘要和裁切参数。用户确认的镜头可在该曲计划的 reference_lock 固定原片摘要和时间码。现有已复核版本优先于批处理的重新选帧。

## 选帧与母图

- 同一机位优先选眼睛自然睁开、眉头舒展、自信或自然微笑的瞬间。生成后放大对照眼周、镜架、配饰和身后人脸；保留原片神情，额外生成人脸或眼镜时退回重做。
- 独唱看主唱能否在缩略图中辨认，检查眼睛、话筒、舞台投屏和伴奏者。合唱可选主唱正面单人镜头；选同框时同时检查两位主演，群舞可以保留主唱与舞者的代表性舞台造型。队歌 MV 可以选球场或球迷。
- 先试横竖裁切。focus 表示原帧归一化焦点，span 表示必须保留的横向范围，zoom 控制放大程度。检查固定在左上角的品牌和底部标题是否挡脸。
- 将清理过台标的参考图交给 FIBO。比较原片与无字母图，逐一核对人物数量、姿态、眼神、乐器和背景。在原片空背景中出现新人物时，优先保留原舞台，只合成位置吻合的前景。仍有失真时，仅取笔触、色调或使用原帧保真调色。任务记录标明实际处理方式。
- 母图派生 B站 1920×1080、1440×1080，以及抖音 1080×1440、1440×1080。逐列看主角大小、人物位置、品牌遮挡和标题字号。

## 本地运行

使用项目虚拟环境，从仓库根目录运行以下命令。批量生图会生成待复核产物。打开 shortlist.jpg 比较选帧，打开 review.jpg 对照原片、处理输入、母图和四版封面。

```sh
.venv/bin/python -m workflow.reviewed_cover shortlist 候选请求.json 候选目录
.venv/bin/python -m workflow.reviewed_cover stage 选定请求.json 试排目录
.venv/bin/python -m workflow.reviewed_cover publish 试排目录 --review-hash 已看过的版本摘要
.venv/bin/python -m workflow.reviewed_cover verify 试排目录 --route 页面中的演唱会或歌手标识
```

发布时核对已审文件摘要并保存上一版清单。验证从实际页面接口取回四张图，逐张检查内容摘要及尺寸，并核对专辑缩略图。只有对应版本验证通过才计入逐曲报告。FIBO 生图耗时、任务时间与峰值内存取自运行记录，本地调色单独标识。

指定完整 AI 时，选定请求使用 `mode: oil`，发布模型直接生成的整张母图。保真调色、色调迁移以及局部人物合成可用于比较。它们独立记录，不计入完整 AI 母图数。直接生成的画面出现额外人物或改变主要动作时，调整参考裁切或提示词后重新推理，逐比例复核再发布。

### 标题与特殊符号

节目合辑可在该曲 `song.json` 中固定 `cover_title` 和 `cover_subtitle`。明确的副标题按整行原文排版，不再自动追加演出名；母图、已审裁切和左上角品牌沿用当前版本。`collection_display_name` 固定该条在 B站合集内的显示名，独立于投稿标题。超级碗系列使用「20xx 届超级碗中场秀」，封面副标题最多列前两位歌手的中英文名称，多人加「等」，合集按年份升序。

按字素簇排版包含 emoji 的标题。普通文字沿用封面标题字体，彩色符号用 Apple Color Emoji 绘制，两部分共用宽度测量和居中基线。四个输出都在实际 JPEG 上核对符号、主唱眼睛和左上角标记。生成输入裁成接近母图的横纵比，并留出头顶空间；若模型仍把额头或双眼截去，重做母图后再提交。
